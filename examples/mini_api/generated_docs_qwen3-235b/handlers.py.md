### `class UserHandler`

Обрабатывает операции API, связанные с пользователями.

#### Методы

##### `__init__(storage: InMemoryStorage) -> None`

Инициализирует обработчик пользователей с использованием хранилища в памяти.

**Параметры:**

- `storage` (`InMemoryStorage`) — экземпляр хранилища в памяти для хранения данных пользователей

**Побочные эффекты:**

Присваивает переданное хранилище внутреннему атрибуту self._storage.

**Смотрите также:**

InMemoryStorage

##### `get_user(user_id: int) -> ApiResponse`

Получает пользователя по его идентификатору из внутреннего хранилища. Если пользователь не найден, возвращает ответ с кодом 404, иначе возвращает данные пользователя с кодом 200.

**Параметры:**

- `user_id` (`int`) — Уникальный идентификатор пользователя, который необходимо получить

**Возвращаемое значение:**

- `ApiResponse` — Объект ответа, содержащий статус и тело с данными пользователя или сообщением об ошибке

**Граничные случаи:**

Если user_id не существует в хранилище, возвращается ответ с кодом 404 и сообщением 'not found'.

**Примеры:**

user_handler.get_user(123)  # Возвращает ApiResponse со статусом 200 и данными пользователя, если найден; иначе — 404 с ошибкой

**Смотрите также:**

InMemoryStorage, ApiResponse

##### `create_user(name: str, email: str) -> ApiResponse`

Создает нового пользователя с заданным именем и email, сохраняет его в хранилище и возвращает ответ с идентификатором пользователя.

**Параметры:**

- `name` (`str`) — имя пользователя
- `email` (`str`) — email пользователя, который будет нормализован перед сохранением

**Возвращаемое значение:**

- `ApiResponse` — объект ответа с кодом состояния 201 и телом, содержащим идентификатор созданного пользователя

**Побочные эффекты:**

Сохраняет данные пользователя в хранилище; изменяет состояние хранилища.

**Примеры:**

user_handler.create_user('Анна', 'anna@example.com')

**Смотрите также:**

normalize_email — нормализует email перед сохранением
