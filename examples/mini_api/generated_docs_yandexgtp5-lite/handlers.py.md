# Модуль `handlers.py`


Модуль с HTTP-подобными обработчиками API (упрощённый пример).

**Содержание:**

- [Классы](#классы)

## Классы

### `class ApiResponse`

Класс для представления ответа от API.

**Поля:**

- `status` (`int`) — —
- `body` (`dict[str, Any]`) — —

### `class UserHandler`

Класс для обработки операций, связанных с пользователями в API.

#### Методы

##### `__init__(storage: InMemoryStorage) -> None`

Инициализирует обработчик пользователя с заданным хранилищем данных.

**Параметры:**

- `storage` (`InMemoryStorage`) — хранилище данных для пользователя

**Возвращаемое значение:**

- `None` — N/A

**Побочные эффекты:**

Инициализация поля _storage

##### `get_user(user_id: int) -> ApiResponse`

Возвращает данные пользователя по его ID.

**Параметры:**

- `user_id` (`int`) — ID пользователя

**Возвращаемое значение:**

- `ApiResponse` — Объект ApiResponse с HTTP-статусом 200 и телом в виде данных пользователя или с HTTP-статусом 404 и телом с ошибкой 'not found'

**Граничные случаи:**

Возвращает ошибку 404 (not found), если пользователь с указанным ID не найден.

**Примеры:**

get_user(123)

##### `create_user(name: str, email: str) -> ApiResponse`

Создаёт пользователя в системе с указанным именем и email.

**Параметры:**

- `name` (`str`) — Имя пользователя
- `email` (`str`) — Электронная почта пользователя

**Возвращаемое значение:**

- `ApiResponse` — Ответ API с созданным пользователем

**Примеры:**

[{"name": "Иван", "email": "ivan@example.com"}]

**Смотрите также:**

def normalize_email(email: str) -> str — Приводит email к нижнему регистру и удаляет начальные и конечные пробелы для хранения.
