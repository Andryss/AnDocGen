# Индивидуальное задание

**Тема**: Реализация метода оценки качества сгенерированной технической документации из сходного кода

## Рабочий план-график

| № этапа | Название этапа | Период | Задание |
|---------|----------------|--------------|---------|
| 1 | Инструктаж обучающегося | 1 | Инструктаж обучающегося по ознакомлению с требованиями охраны труда, техники безопасности, пожарной безопасности, а также правилами внутреннего трудового распорядка |
| 2 | Заполнение и утверждение задания | 48 | Заполнить в разделе Практика задание на НИР, согласовать с куратором практики, отправить на согласование руководителю практики. |
| 3 | Анализ методов оценки качества сгенерированной технической документации | 35 | Найти и изучить не менее 10 научных работ, рассматривающих различные методы и подходы к оценке качества автоматически сгенерированной технической документации и документации исходного кода. Для поиска использовать научные публикации из открытых источников и библиографических систем (например, Google Scholar, arXiv, IEEE Xplore, ACM Digital Library). Для каждой работы определить применяемые методы оценки, оцениваемые характеристики документации, необходимые входные данные. На основе изученных работ выполнить классификацию применяемых методов. Результатом этого этапа является документ, содержащий: список всех проанализированных научных работ со ссылками на источники; перечень выявленных методов оценки качества; классификацию методов; сравнительную таблицу методов с указанием оцениваемых характеристик, необходимых входных данных, преимуществ и ограничений. |
| 4 | Разработка метода оценки качества сгенерированной документации | 28 | На основе результатов анализа существующих подходов разработать метод оценки качества технической документации, генерируемой из исходного кода. Определить не менее 4 характеристик качества документации, подлежащих оценке. Для каждой характеристики определить способ вычисления оценки, необходимые входные данные, диапазон значений и правила интерпретации результата. Определить алгоритм формирования итоговой оценки качества на основе отдельных показателей. Определить последовательность выполнения оценки и требования к входным и выходным данным метода. Результатом этапа является документ, содержащий: перечень оцениваемых характеристик качества; таблицу показателей с указанием входных данных, способа расчета, диапазона значений и правил интерпретации; формулы или алгоритмы расчета показателей и итоговой оценки; блок-схему алгоритма оценки качества; описание формата входных и выходных данных. |
| 5 | Реализация метода оценки качества | 28 | Реализовать разработанный метод оценки качества в составе прототипа разработанной в предыдущем семестре системы. Разработать программные компоненты для получения необходимых данных об исходном коде и сгенерированной документации, вычисления отдельных показателей и формирования итоговой оценки качества. Интегрировать разработанные компоненты в существующий процесс генерации документации. Реализовать сохранение результатов оценки в структурированном формате. Провести функциональную проверку реализации на тестовых данных. Результатом этапа является документ, содержащий: описание структуры реализованного модуля оценки; диаграмму, описывающую его взаимодействие с компонентами прототипа системы; описание ключевых разработанных классов и методов; примеры сформированных результатов оценки. |
| 6 | Формирование набора проектов для апробации | 14 | Сформировать набор из не менее 10 проектов с открытым исходным кодом для проведения апробации реализованного метода оценки. Для поиска использовать открытые репозитории программного обеспечения (например GitHub, GitLab, репозитории университета). Определить критерии включения проектов в выборку. Отбирать проекты, содержащие достаточный объем исходного кода и техническую документацию, пригодную для проведения оценки. В выборке должны присутствовать проекты различного размера и назначения. Для каждого проекта зафиксировать используемую версию и основные характеристики исходного кода и документации. Результатом данного этапа является документ, содержащий: перечень критериев отбора проектов; список отобранных проектов со ссылками на репозитории и указанием используемых версий; сравнительную таблицу проектов с количественными характеристиками исходного кода и документации. |
| 7 | Проведение апробации метода оценки качества | 21 | Провести апробацию реализованного метода оценки на сформированном наборе проектов. Для каждого проекта выполнить генерацию технической документации и провести ее оценку разработанным методом. Зафиксировать значения отдельных показателей и итоговой оценки качества. Провести сравнительный анализ полученных результатов. Рассчитать сводные показатели по экспериментальной выборке. Выявить случаи получения высоких и низких оценок, определить причины результата и ограничения разработанного метода. На основании полученных данных сформулировать выводы о применимости разработанного метода. Результатом этапа является документ, содержащий: таблицу результатов оценки проектов; сводные статистические показатели; графики сравнения результатов между проектами; перечень выявленных ограничений метода; выводы по результатам апробации. |
| 8 | Оформление отчетных документов | 91 | 1. Должно быть подробное описание задач по этапам. Результаты задания необходимо разместить в приложения. 2. Оформление должно быть выполнено в соответствии с методическим пособием (https://books.ifmo.ru/file/pdf/2622.pdf). 3. Структура документа: титульный лист, введение, основная часть, заключение, приложения. 4. В основной части подробно описывается выполнение задач 2-6 этапов, в приложении помещаются результаты данных этапов. 5. Отчет необходимо подгрузить в модуле практика как "письменный отчет". |
